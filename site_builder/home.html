Abstract

The OWASP Top 10 for Agentic Applications (2026) sets out the principle of least agency: an AI agent should get only the access its task needs. Agents connected to business systems through the Model Context Protocol (MCP) often break it, running every tool under one shared credential.

This report tests the principle in a lab. An agent with four tools was deployed on AWS with default settings, threat modelled with STRIDE, hardened with four configuration changes and re-tested. It also sets out how the same problem appears on Azure, and states its limitations.

Key findings

Tested findings come from tests run in the AWS lab. Analysis findings come from the threat model and Microsoft's documentation.

  1. Tested A shared credential is the root exposure. When every tool runs under one role, a read-only task can perform financial writes. One identity per tool closed this.
  2. Tested Identity limits damage; detection doesn't stop it. Content inspection flagged the injected instructions, but it is probabilistic. Per-tool identity is what caps what a steered agent can do.
  3. Tested Attribution has to be designed in. Default logs showed an API call, not the user, agent and tool together. Requiring the user's identity on every call fixed this.
  4. Analysis The threat model found what the tests missed. Three tests covered three of sixteen threats. Bulk export and the confused deputy need their own controls.
  5. Analysis Azure needs its own design, not a service mapping. Its over-provisioned account is usually one managed identity shared by every tool, and managed identity tokens can be cached for around 24 hours.
