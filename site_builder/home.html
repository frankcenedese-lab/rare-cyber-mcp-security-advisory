Abstract

AI agents connected to business systems through the Model Context Protocol (MCP) commonly run every tool under one shared credential, can be steered by content they read, and leave logs that can't attribute an action to a person. This report describes a lab built to examine those risks. An agent with four tools (read, financial write, approval and export) was deployed on AWS with default settings, assessed, hardened with the TRIAD framework, and re-assessed. An Azure reference design for the same lab sets out where Azure behaves differently, in particular that its over-provisioned account is usually one managed identity shared by every tool; Azure results will be added once tests are run in a tenant.

The baseline failed three controls: least privilege (NIST SP 800-53 AC-6), input validation (SI-10) and audit generation (AU-12). All three passed after hardening in the AWS lab. A subsequent STRIDE threat model identified sixteen threats across five trust boundaries, including two that the original tests only partly covered: excessive data export and the confused deputy problem. An identity analysis separates the four identities in each tool call (user, agent, MCP server and downstream API) and places the lab at level 2 of a five-level agent identity maturity model: each tool has its own role and the user is recorded, but authorization isn't yet capped at the user's rights. The report documents each configuration and policy change before and after, defines thirteen test cases with an automated harness that records hashed evidence, and states its limitations and residual risk.

Key findings

Tested findings come from tests run in the AWS lab. Analysis findings come from the threat model and identity analysis; their tests are defined but not yet run.

  1. Tested Shared credentials are the root exposure. When every tool runs under one identity, a read-only task can perform financial writes. Per-tool identities closed this in the lab.
  2. Analysis Checking the agent isn't enough. The gateway must also check the rights of the person the agent acts for, or the agent becomes a confused deputy.
  3. Analysis Export is its own privilege. Read and write rights shouldn't imply the right to extract data in bulk.
  4. Tested Attribution needs design. Default logs show an API call, not the user, agent and tool together. Recording the user's identity on every call fixed this in the lab.
  5. Analysis Per-tool roles are only level 2 of 5. Expert-grade agent identity needs delegation with audience-bound tokens, parameter-level policy, separation of duties, just-in-time elevation and measured revocation.
  6. Analysis Testing without a threat model overstates coverage. Before the model, three tests appeared to cover the lab; afterwards, they fully covered three of the ten threats in the first model.
